# Development Rules

## 1. Branch Workflow

- `main` is the stable branch.
- Each contributor works on their own branch.
- Do not make direct changes to `main`.
- Pull the latest changes before starting work.
- Push completed work to the contributor's branch.
- Use Pull Requests to merge work into `main`.

## 2. Branch Naming

Use clear branch names such as:

- `trisha-day1`
- `tanmayi-day1`

## 3. Commit Naming

Use short and descriptive commit messages.

Examples:

- `Add repository development rules`
- `Add vendor model`
- `Add quote API`
- `Update vendor dashboard`

## 4. Pull Request Workflow

1. Complete the work on the assigned branch.
2. Test the changes locally.
3. Commit and push the changes.
4. Open a Pull Request on GitHub.
5. Review the changes.
6. Resolve any review comments.
7. Merge into `main` after approval.

## 5. Collaboration Rules

- Communicate before changing shared files.
- Pull/fetch the latest changes regularly.
- Do not overwrite another contributor's work.
- Resolve merge conflicts carefully.
- Keep commits focused on one task.
- Never commit passwords, API keys, database credentials, or `.env` files.

## 6. Code Quality

- Keep the project structure organized.
- Use clear and meaningful names.
- Test changes before pushing.
- Keep documentation updated when necessary.
